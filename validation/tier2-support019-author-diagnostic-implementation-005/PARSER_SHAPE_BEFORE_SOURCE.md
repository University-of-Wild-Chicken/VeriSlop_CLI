# Closed parser refinement before implementation

The root specification and the version001 observability specification govern this candidate. This document fixes the remaining concrete parser API choices before source is written. No native response protocol is replaced. The diagnostic branch is enabled only with an exact caller boolean `fixture_failure_allowed=True` representing the registered fixture SYSTEM permission; its default is False. A five-key object is always a failure, even with complete ordinary fields. Four-key success acceptance remains outside this evidence-only parser.

`parse_failure(raw, *, fixture_failure_allowed=False, exposed_references=())` accepts exact bytes or str and returns a closed UNATTESTED evidence wrapper containing the raw-byte SHA, parsed report, success=False, no discharged claims and historical_cause=UNAVAILABLE. It never reads a file, resolves a path, invokes producer/runtime APIs or infers whether a reported attempt executed. JSON duplicate keys, floats/nonfinite numbers, unsafe integers and non-scalar Unicode are rejected. Counts and cursor/byte values reject boolean substitution. The closed shapes/enums and nullable unavailable values follow version001.

AlreadyExposedReference is concretized as exactly `{path: nonempty scalar string, sha256: lowercase sha256 string, byte_count: exact nonnegative safe integer}`. Only exact typed members of the caller's explicitly supplied list/tuple of such refs are accepted; duplicate allowlist entries are rejected. This authenticates membership, not file content or the caller's observation provenance. Opaque chunk IDs may be reported in OwnOperation but cannot become invented filesystem refs. Caller-supplied provenance and independent reproduction remain external explicit trust.

Partial markers are arrays of nonempty scalar strings; field_roots is a partial map over /system and /user containing strict lowercase SHA strings; field_eof and field_chars retain exactly /system and /user with strict bool and nonnegative safe integer values. The parser validates shapes only. Observation.scope=complete remains an UNATTESTED author claim, never an attested complete tool result. Unavailable observations/reproductions remain permissible honest failures. Reproduction and self-critique literals are data, never executable code. No semantic sufficiency, global minimality, historical causation or genuine observation is inferred from them.

Closed VIEW retains exact inventory/field keys, operation/selector bounds, integer cursor, 256..8192 cap and 128..cap-1 reserve. Closed CONFIRM retains exactly nonempty chunk_id and exact boolean outer_output_intact; False remains a legal reported failing attempt. Nullable operation bounds are checked whenever present, with reserve less than cap when both are reported. A retry object is exactly a closed VIEW or CONFIRM or null. No extra inferred stage/cursor consistency constraints are introduced.

Source controls will include concrete malformed objects and exact expected rejection codes, reference membership forgery, claimed authority, malformed Unicode/JSON, and the successful-looking five-key case that must remain failure evidence. Source fidelity will compare every other module AST, the old instruction's exact prefix, source-derived independent message reconstruction and unchanged capture function ASTs. All controls are unrelated source development only; no model, VIEW, task, Lean or qualification execution is authorized.
