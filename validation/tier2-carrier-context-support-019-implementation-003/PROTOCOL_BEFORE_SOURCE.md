Each performs exactly one unchanged inline reader call, forwards the full actual tool result, then stages `{reference, view, result}` under its own pending key. Staging never changes accepted cursors or accumulated content. The full reader and original command prefix remain byte-identical to production9930.

CONFIRM is an explicit zero-VIEW, zero-tool exception. After seeing an intact outer response, the author edits only closed `CONFIRM = {chunk_id: ACTUAL_CHUNK_ID, outer_output_intact: true}`. It reads only current own pending/checkpoint keys. The fixed validator checks strict numeric successful complete actual status, exact parsed canonical JSON/no duplicate or extra keys, reference binding, output cap/reserve, request identity/totals, explicit selector/start/end/next/UTF-8 sizes and Unicode scalars. Inventory creates an own original-field checkpoint. Contiguous valid field views append their exact decoded content. Revisits must equal wholly accepted original ranges and do not append. System explicit EOF precedes user; both empty fields require explicit EOF. Errors, false acknowledgement, unmatched chunk or reference, gaps, malformed/nonzero/truncated output and mismatched replay reject without writing accepted state. Outer truncation must be followed by the same-cursor VIEW retry, never CONFIRM. Confirmation is a tool-forwarding-trust observation, not hidden-envelope or semantic-consumption attestation.

CONFIRM prints only its bounded availability summary. Accepted state retains exact original decoded content and actual observations with request identities. Neither VIEW nor CONFIRM selects, increments or executes any next VIEW automatically. Each next closed cursor is still the author's explicit choice from the last fully observed response.

It reads only own checkpoint; verifies own reference/totals/scalars; serializes only exact accumulated decoded original fields into an inline stdlib Python command with `-I -B`. Python reads no files/helper/carrier/expected answer/network and computes SHA-256 over strict UTF-8 of these strings. It forwards exactly one full actual result, never changes view state or synthesizes markers/answer/ACCEPT. It may store its raw own hash result for compression. This is the newly allowed author-side cryptographic capability; it is not a precomputed oracle.
