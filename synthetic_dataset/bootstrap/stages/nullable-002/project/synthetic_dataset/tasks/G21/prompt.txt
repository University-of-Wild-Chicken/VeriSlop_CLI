Software engineering task G21: TTL idempotency records without sliding expiry

Implement solution.py with solve(data). Use only the Python standard library. Do not read files, use the network, print, or retain state across calls. All inputs conform to this specification; return JSON-compatible values. Input {ttl,requests}, ttl positive; requests {at,key,payload}, nondecreasing integer at, ASCII key and ASCII payload. Before each request expire all records whose expires<=at. A new key stores payload, response=payload.upper(), expiry=at+ttl, and returns {status:"new",value:response}. A live matching payload returns {status:"replayed",value:response} without extending expiry. A live differing payload returns {status:"conflict",value:null} and does not change the record. Return {results,live_keys}, sorted live keys after the last request; there is no implicit final time advance.

Implement a pure deterministic Python 3 function solve(data) in solution.py. Use only the standard library, no external I/O. The function receives a JSON value and returns a JSON-serializable value. Preserve the specified input/output structure and exact ordering.

Public examples (additional held-out cases will be scored):
[{"input": {"requests": [{"at": 0, "key": "k", "payload": "a"}, {"at": 2, "key": "k", "payload": "a"}, {"at": 3, "key": "k", "payload": "b"}], "ttl": 3}, "output": {"live_keys": ["k"], "results": [{"status": "new", "value": "A"}, {"status": "replayed", "value": "A"}, {"status": "new", "value": "B"}]}}, {"input": {"requests": [{"at": 0, "key": "k", "payload": "a"}, {"at": 1, "key": "k", "payload": "b"}, {"at": 2, "key": "j", "payload": "z"}], "ttl": 2}, "output": {"live_keys": ["j"], "results": [{"status": "new", "value": "A"}, {"status": "conflict", "value": null}, {"status": "new", "value": "Z"}]}}]
