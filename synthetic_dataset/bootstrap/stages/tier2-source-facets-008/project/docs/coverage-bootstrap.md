# Specification-first coverage bootstrapping

This specification precedes implementation of the next coverage increments. The
goal is a larger generic executable contract language and an actual strict Tier 0
TESTED result from original corpus task D21. The stopped full-corpus experiment is
immutable historical evidence; new sources require new run IDs and input roots.

## Ordered increments

1. **Agent protocol and context.** Specify a capability-gap response separately
   from contract proposals. Validate exact active obligation identities, retain the
   report without proof authority, and allow bounded faithful representation
   correction. Critics and fresh repair packages receive the exact rejected raw
   response and hash-validated retained context. No milestone follows from a gap
   report. Run the original D21 prompt through the strict CLI; record its actual
   terminal stage, including remaining coverage gaps.
2. **Nullable values and branching.** Specify a generic `Option` carrier preserving
   Python `None` or its actual non-null value, Boolean conditional expressions and
   option elimination. Reject carriers whose Python representation is ambiguous.
   Extend compiler, Lean AST reconstruction, denotation checks, oracle, codecs,
   generators, witnesses and counterexample replay together. Run the original D21
   prompt again against a separately frozen source root. A remaining primitive
   gap is evidence for the next increment, not a successful TESTED result.
3. **Arithmetic sequence coverage.** Specify and implement generic input-dependent
   range and signed floor division. Run original corpus instance A23 (the signed
   floor-sum kernel) through the complete strict pipeline. This smaller composition
   must attain the same strict TESTED, origin, build and independent-case criteria.
4. **Grouping sequence coverage.** Specify and implement generic input-dependent range,
   total indexing, signed arithmetic and scalar ordering/deduplication needed for
   D21, without task-specific functions or templates. Match the pinned Lean
   semantics exactly. Run the original D21 prompt again. Completion requires actual
   native strict CLI PASS, all required TESTED milestones, finite VERIFIED closure,
   two successful isolated clean builds, exact artifact origin and every original
   public/hidden D21 case passing in two independent grader processes.

Each increment's detailed grammar and semantics must be written before its code.
After an increment's coherent source snapshot is frozen, development of the next
specified increment may proceed independently. Its model run starts only after
the preceding run's outcome has been retained. No in-flight snapshot is changed.
Increment-specific specification changes are preserved; source changes during a
frozen model run invalidate that run rather than being silently inherited.

## Strict run boundary

Generation starts with the original natural-language prompt and its public examples.
Every interpretation, formalization, Lean check/proof, accepted-AST reconstruction,
implementation, linkage, generated test campaign, configured adversarial review
and final closure gate remains active. No hand-authored positive candidate, fixed
task answer, task dispatch, oracle import or artifact-first fallback is supplied.
The obligation JSON used downstream comes from the accepted formal artifact.

Use fresh GPT-6.1 Sol collaboration agents for each role call, with no prior
conversation fork. Exact request/final bytes and their origins are retained. The
transport requests Sol; provider identity, model snapshot, sampling and token usage
are unattested. Model instructions limit reads to the carrier, but that restriction
is not mechanically enforced. This is an engineering bootstrap, not a new unbiased
100-task benchmark or an equal-compute comparison.

Each run has at most 128 logical model calls, 24 per instance and two outer contract
repair rounds. There are no generation, proof-search or review wall deadlines.
Candidate execution retains the native finite time/memory/isolation limits.
Hidden cases, expected outputs, generators and historical model answers are not
model context or repair feedback. Independent grading is performed only after
generation terminates; missing artifacts have no executed code observations.

The origin auditor must reconstruct recognized capability reports with the same
assembler and exact recorded response bytes. Their retained marker/report pair is
negative evidence only: no frozen challenge, acceptance, proof or implementation
may accompany that negative placeholder. A changed report cannot inherit its
origin receipt. This prevents honest capability reports from becoming false
provenance failures without granting them contract authority.

## Mechanical checks and evidence

Before each run freeze the specification, exact prompt and corpus hashes, source,
configuration, endpoint selection, verifier registry and host environment. Existing
source inventories, origin checks and candidate graders are reused with an explicit
single-instance bootstrap selection; no incomplete run is represented as a full
corpus result. Store every rejected/accepted JSON and Lean artifact, memory snapshot,
critic report, grader observation and native report. A new source root never reuses
an earlier PASS.

Primitive acceptance requires real Lean compilation/kernel replay and exact
denotation equality after AST reconstruction, plus independent known-answer
boundary tests. Regression checks must reject ambiguous nullable representations,
tampered handoffs, unknown fields/IDs and changed compiler semantics. LLM judgment
alone cannot discharge correspondence or decide closure.

Trusted surfaces include the existing pinned Lean kernel/runtime, registered
verifiers, Python and isolation mechanisms, OS/filesystem/hardware, hashing,
privileged model-final copying and original corpus oracle. Formal model proofs and
finite tests do not prove natural-language interpretation or universal Python
correctness. END_TO_END_VERIFIED is outside this Tier 0 surface.

## Outcome

Report each increment as actually observed, distinguishing a successful primitive
regression, accepted contract, TESTED attainment and complete strict CLI success.
BLOCKED and infrastructure failure remain explicit. The final coverage claim is
only the newly supported grammar and the successfully tested corpus instance;
recursive JSON and full graph/text coverage need later specified increments.
