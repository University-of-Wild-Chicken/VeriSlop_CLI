# Review guidance for the admitted target

This specification precedes the guidance correction. The VSCore 0.3 review
policy admits `target_case` at implementation and release, backed by pinned
kernel replay of the exact source and accepted value predicate. The review
system prompt and checkpoint restriction nevertheless say Python only. That
contradiction can discourage an available concrete search; it does not by itself
make acceptance impossible because mechanical probes remain available.

The system prompt must describe both registered target replay paths without
granting a new capability. Supervisor-selected checkpoint guidance follows the
existing closed proposal policy: interpretation and formal-contract review
still prohibit target execution; implementation and release permit target cases
only when the policy admits them, using supported accepted binder shapes. An
older VSCore backend without kernel replay continues to allow only its existing
mechanical probes. Python source-violation probes remain Python specific.

No replay implementation, target oracle, voting rule, required review scope,
kernel limit, bridge requirement or lifecycle gate changes. Ground probes are
bounded searches, never substitutes for universal refinement. Regressions must
cover the backend/checkpoint capability matrix and retain concrete protocol
repair and counterexample replay checks.

## Bound release-review context

This specification precedes the release prompt projection. An independently
authored two-symbol native VSCore 0.3 fixture exposed a 101,356-token release
review packet before its 2,048-token output reservation. Exact inline sharing
alone reduced it to about 50,103 tokens, still above the configured 40,960.
These are offline fixture measurements, not a successful live project run.

For VSCore 0.3 release review only, retain the complete original `packet.json`
unchanged. The existing native mechanical snapshot validator and deterministic
review-target projection continue to consume that full packet. The model view
may replace exactly two kinds of redundant mechanical detail with bound
references: `mechanical_snapshot.execution_inventory` and each
`mechanical_snapshot.builds[i].outputs`. A reference names the retained packet,
exact JSON pointer, canonical value hash and byte count. The view binds the
complete original packet's canonical digest and identifies these details as
retained but not inline. No model-generated summary replaces them.

Keep all other fields exact, including both build statuses and errors, every
claim and dependency, provenance, original request, obligation scope, accepted
Lean source, delivered source and proof, generated bridge goal and certificate,
binding inventory, current review policy and supported concrete probes. Raw
mechanical output detail is checked by the registered native verifiers; the
reviewer must not claim to have inspected referenced detail. It can challenge
any current mechanical claim through the existing independently replayed probes.
This display projection assigns no outcome and never bypasses a validator.

The complete view then uses the lossless inline codec specified in
`bootstrap-implementation-context.md`. Before dispatch, restoration must verify
the full packet binding and exact equality with a freshly derived view; unknown,
changed or missing view fields/references fail. Retain the view once beside the
full packet. Bind the codec and projection implementation to review configuration
and consensus verifier identity. Existing target roots, ballot scope, mechanical
veto, quorum, counterexample replay and final closure validation remain intact.
Earlier checkpoints and other backends retain their existing prompt format.

Checks cover exact restoration, every replaced path, unrelated similarly named
fields, malformed references and changed full packets. Exercise real review
dispatch and malformed-ballot correction with the same full scope. Measure the
registered tokenizer without raising context or lowering output allowances.
Larger packets still fail explicit capacity admission; the fixture does not
establish universal fit or authorize model acceptance.
